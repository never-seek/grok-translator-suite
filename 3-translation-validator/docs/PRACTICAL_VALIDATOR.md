# Practical 3-Tier Validator 工业级小说翻译质检规范

## 1. 诞生背景与核心痛点

在传统的 LLM 网络小说翻译流水线中，通常采用**二元判定模式（非 PASS 即 FAIL）**：
质检程序在检测到任何未翻译韩文字符或英文字符时，直接拒绝当前输出并抛出 HTTP 502，或者强制触发重试/Fallback。

**二元判定在真实工业场景中导致的严重灾难**：
1. **单个孤立残词误杀**：万字小说长文中，如果模型在极个别生僻词或修饰语上留存了一个单字（如 `그대로`），整个 2000~4000 字的 chunk 会被整段丢弃，触发熔断。
2. **现代英文借词误杀**：小说中角色谈及 `YouTuber`、`underdog`、`logo`、`cosplay`、`Checkmate`、`ESSE`（香烟名）等自然英文词汇，二元检测器会误判为“英文污染”并拒绝交付。
3. **网络语气拟声词误杀**：韩文网文常见的网络聊天拟声子音（Jamo），如 `ㅋㅋ`（笑）、`ㅠㅠ`（哭）、`ㅇㅅㅇ`（表情）、`ㄷㄷㄷ`（发抖），在中文网文中完全属于良性表达，被二元质检视为“未翻译韩文”。
4. **故意拟真文本与系统 Bug 误杀**：游戏异界文中的系统崩溃台词（如 `(벨겟굶눋뜩뢰겆뀐걸흐흐흐)`）、外星语言，作者原本就是故意编写的乱码，译者本来就应当原文保留，却被二元质检误判为“原文复读”进而 502 熔断。

> 在过去万次调用基准测试中，**超过 95% 的 502 熔断并非因为翻译崩塌，而是被过度严格的质检器误伤！**

## 2. Practical 3-Tier 分级判定设计哲学

**固定核心职责**：
> **“防止不可接受的灾难性翻译结果进入用户正文，同时绝不因为局部可读瑕疵制造服务故障。”**

质检正式区分三个层级：

| 质检层级 | 严重程度 | 处理动作 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **PASS** | 绿色 / 完全合规 | 直接首轮毫秒放行交付 | 完全翻译、术语匹配、结构完整 |
| **WARN** | 黄色 / 良性瑕疵 | 记录警告遥测，**直接放行交付**，不触发 Fallback，不造成 502 | 孤立韩文残词、英文品牌/外来词、网络 Jamo 表情、符合规则的故意乱码 |
| **HARD FAIL** | 红色 / 灾难性错误 | **严格拦截**，阻断交付，自动触发 Fallback 模型重试 | 自然韩语整句未翻复读、丢键、结构损坏、空输出、行对齐错位 |

## 3. 规则细节规范

### (1) WARN 警告级别规则
* **`hangul_residual`**：译文中包含孤立的韩文音节，但未形成大段连续韩文语句。
* **`english_contamination`**：译文中出现常见英文词汇、人名缩写、品牌名或游戏专有名词。
* **`source_jamo_preserved`**：原文中出现韩文字母（Jamo），译文原样保留该语气符号。
* **`OPAQUE_LITERAL`**：命中确定性正则特征的故意乱码台词、异形破损文本。

### (2) HARD FAIL 致命拦截规则
* **`raw_repetition_exact`**：译文与原文韩文逐字完全一致，且未命中 OPAQUE 例外（代表模型拒翻或原文复读）。
* **`raw_repetition_similar`**：译文与原文语义高度重叠但未翻译。
* **`structural_failure`**：JSON 格式损坏、键值对丢失、非合法 JSON。
* **`empty_output`**：原文有非空内容，译文输出为空字符串。
* **`line_shift`**：行数与原文不匹配，发生行错位漂移。
