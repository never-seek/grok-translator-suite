# OPAQUE_LITERAL 确定性异形文本豁免规范

## 1. 为什么需要 OPAQUE_LITERAL？

在网络小说（尤其是奇幻、网游、克苏鲁、系统流、科幻）中，作者常会创作特殊的非自然语言文本：
* **系统 Bug / 精神错乱台词**：如 `(벨겟굶눋뜩뢰겆뀐걸흐흐흐)`
* **外星人 / 信号损坏对话**：穿插 HTML 标签、特殊符号与断裂字母，如 `“이.`0ㅇ거 3$<i>ㅂ</i>ㄱP<i>사sg</i>K<u>ㄹ게</u>ㅔ<b><i>ㅛ</i></b>.”`
* **发狂状态下的长连词**：如 `벨둡냈깖러뒝렌궁베똑냇렷록긱띰빕`
* **崩溃对话人**：如 `벨덱냇벋뒨됩흐흐 : 벨뜹꿨흐`

在正常翻译中，**高级模型（如 Grok Reasoning）会选择原汁原味地保留这些作者刻意编排的乱码符号**。
但在常规检测器看来，这属于：
```text
source_line == output_line (韩文完全一致) -> 判定为 raw_repetition_exact (未翻译) -> 强制熔断 502
```
这构成了网文翻译中最隐蔽、最难解决的“伪未翻译”误伤问题。

---

## 2. 判定原则与确定性正则分类器

`OPAQUE_LITERAL` 并非模糊的启发式算法，而是经过严格生产校验的**确定性规则集合**：

1. **`interleaved_html_mixed_scripts`**：
   - 特征：字符串中交替出现 HTML 标签（`<i>`、`<b>`、`<u>` 等）、特殊符号、拉丁字符与孤立韩文字母。
   - 场景：外星语、无线电干扰音效。
2. **`bracketed_unspaced_hangul_len_12`**：
   - 特征：被括号（`()`、`[]` 等）包裹，且内部包含 10 个以上连续无空格的韩文生僻音节。
   - 场景：系统音效、内心怪叫、机械报错。
3. **`corrupted_dialogue_speaker_len_8`**：
   - 特征：形如 `Speaker : Message` 结构，但说话人名由 8 个以上连续无空格特殊韩文拼缀而成。
   - 场景：崩坏 NPC、无名怪声。
4. **`long_unspaced_hangul_token_len_16`**：
   - 特征：单 token 长度超过 16 个字符且无任何自然韩语助词、终结词尾特征的异常长串。
   - 场景：乱码字符流、符咒密码。

## 3. 防误放安全红线 (False Positive Prevention)

* 普通自然韩语（如 `그는 문을 열었다.`、`도망쳐!`、`살려줘!`）**绝对不会命中 OPAQUE 规则**，继续严格执行 `HARD FAIL`。
* 在生产环境连续 1051 个真实 chunks 检验中：
  - OPAQUE 命中事件数：`8` 条 Key
  - 成功解救生产 Chunk 数：`2` 次（免死直接放行）
  - **确认误报率 (False Positive)：0.00%**
